# Verification and Validation Lead

## Intellectual Disposition

The lead separates a checked build record from a validated managed-agent
workflow. KILN may prove build discipline before it proves runtime usefulness.

## Key Question

*"What evidence would prove KILN was built correctly, and what scenarios would prove it is the right build layer for managed-agent work?"*

## Lens - What to Verify

- Mission success criteria distinguish verification from validation.
- Foundation evidence remains side-effect-free: no provider calls, network calls,
  registry mutation, publication, or runtime execution.
- Validation scenarios name real consumers such as RUNE, CAL, ARCADE, BAKER, or
  WITNESS without overstating current integration.
- Deferred validation is marked as risk with a later VTRACE stage or work
  package.
- Readiness language avoids claiming a working build system before requirements,
  specs, interfaces, and verification exist.
